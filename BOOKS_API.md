# Книги

Раздел клиента: `/books`, переход с виджета «Книги». Данные сохраняются в PostgreSQL и доступны только владельцу. Используется существующая cookie-авторизация.

Клиентская реализация сохранена отдельным коммитом в локальном checkout `.tmp/finance-bank-screenshots-client`, ветка `codex/books-tab`. Полная копия изменений клиента находится в `frontend/books-tab.patch` этого репозитория. Патч применяется к репозиторию SweetHome командой `git am <абсолютный-путь-к-books-tab.patch>`; перед применением рабочая копия клиента остаётся чистой. Сервер и клиент используют один контракт ниже.

## API

Базовый маршрут: `/api/v1/books`. Все методы требуют авторизации.

| Метод | Маршрут | Результат |
|---|---|---|
| GET | `/` | Список, пагинация, общая статистика библиотеки |
| GET | `/{id}` | Книга |
| POST | `/` | Созданная книга, 201 и Location |
| PUT | `/{id}` | Обновлённая книга |
| DELETE | `/{id}` | 204 |

Чужой или отсутствующий `id` возвращает 404. Неавторизованный запрос возвращает 401. Невалидные данные возвращают 400, `ValidationProblemDetails.errors` содержит ошибки полей.

Параметры списка: `query` (название или автор), `status`, `sortBy` (`UPDATED_AT`, `TITLE`, `AUTHOR`, `RATING`), `page` (от 1), `pageSize` (1–100, по умолчанию 24). Обновление и оценка сортируются по убыванию, название и автор — по возрастанию. Книги без оценки находятся в конце при сортировке по оценке. Символы `%`, `_` и `\` в поиске трактуются буквально.

Ответ списка:

```json
{
  "items": [],
  "page": 1,
  "pageSize": 24,
  "total": 0,
  "hasNext": false,
  "stats": { "total": 0, "wantToRead": 0, "reading": 0, "completed": 0, "onHold": 0, "dropped": 0, "pagesRead": 0 }
}
```

`total` учитывает фильтры; `stats` считает всю библиотеку текущего пользователя.

Создание и редактирование:

```json
{
  "title": "Дюна",
  "author": "Фрэнк Герберт",
  "genre": "Фантастика",
  "status": "READING",
  "totalPages": 640,
  "pagesRead": 120,
  "rating": 5,
  "notes": "Продолжить на выходных"
}
```

Статусы: `WANT_TO_READ`, `READING`, `COMPLETED`, `ON_HOLD`, `DROPPED`. Отсутствующий статус при создании — `WANT_TO_READ`.

Название и автор обязательны: до 300 и 200 символов. Жанр — до 100, заметки — до 5000. Пробелы по краям удаляются; пустые необязательные строки становятся `null`.

Общее число страниц — `null` или целое от 1 до 100000. Прочитано — целое от 0 до 100000, не больше известного общего числа. Для `COMPLETED` с известным объёмом прогресс устанавливается равным объёму. Равенство прогресса объёму само по себе статус не меняет. Оценка — `null` или целое от 1 до 5.

Ответ книги содержит эти поля и `id`, `createdAt`, `updatedAt` (UTC). Поля владельца не принимаются и не возвращаются.

## Обновление

Миграция `20261117181407_AddBooks` создаёт таблицу `Books`, связь с пользователем и индексы. Приложение применяет миграции при запуске. Для поиска кириллицы без учёта регистра PostgreSQL использует Unicode-совместимую локаль базы (например ICU `und`); системная локаль `C` не обеспечивает такое сравнение кириллицы.

## Проверка

- .NET: 362 теста объединённой версии с финансами, включая 20 сценариев Books; модель EF и миграции согласованы.
- Angular: production build; браузерные тесты поиска, отмены устаревших ответов, повторной загрузки, прогресса и сохранности формы.
- Изолированная PostgreSQL 17 с ICU `und`: 46 HTTP-проверок, включая cookie auth, CRUD, комбинированные фильтры, кириллицу в разном регистре и доступ к чужим книгам.
- Отдельный критик проверил итоговый код; блокирующих замечаний нет.

Воспроизводимая HTTP-проверка: `python SweetHomeApi.Tests/Books/http_check.py`. Переменная `BOOKS_QA_BASE_URL` задаёт адрес изолированного тестового API (по умолчанию `http://127.0.0.1:5099`). Скрипт создаёт два тестовых аккаунта, проверяет и удаляет только созданные им книги; результат записывается в `.tmp/books-http-results.json`.

Использован принцип [Gauntlet Loop](https://github.com/robonuggets/gauntlet-loop): реализация → независимая проверка → исправления → повторная проверка. Слепое сравнение с внешним продуктом не проводилось.
